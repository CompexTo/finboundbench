# Master prompt for Codex

You are working inside a local research repository named `purposebound-finance`. Your job is to connect this benchmark to the user's locally running Compex system, execute reproducible experiments, and preserve raw research evidence suitable for an ACM ICAIF paper.

## Non-negotiable rules

1. Do not modify the production Compex code until you have mapped its existing local API, CLI, schemas, authentication and evidence output.
2. Create a new Git branch for research integration.
3. Do not upload customer, employer or private production data. Use only the deterministic synthetic dataset generated by this repository.
4. Never manually edit raw result JSONL files.
5. Every experiment must record Git SHA, configuration hash, policy hash, prompt hash, model identifier, seed, timing, errors and full machine-readable evidence.
6. Do not silently substitute models, endpoints or parameters.
7. The benchmark's primary metric is paired counterfactual influence, not an LLM judge score.
8. Keep Compex and baseline runs semantically equivalent: same task, same allowed information and same model settings where technically possible.
9. Never claim legal compliance. Measure technical properties only.
10. Stop on schema mismatch or missing evidence rather than fabricating a success record.

## Phase 1 — Repository and environment

- Initialize Git if needed.
- Create branch `research/purposebound-finance`.
- Install Python 3.11+ and `pip install -e .[dev]`.
- Copy `.env.example` to `.env` without committing secrets.
- Run `pytest -q` and `python -m purposebench.cli generate --cases-per-workflow 2`.
- Commit the untouched scaffold as `chore: initialize purpose-bound finance benchmark`.

## Phase 2 — Inspect local Compex

Locate the local Compex repository and running services. Document, without changing behavior:

- startup command or Docker Compose files
- health endpoint
- execution submission endpoint or CLI command
- request schema
- response schema
- policy/contract schema
- object upload or data-ingestion path
- output-policy mechanism
- evidence/audit response
- run identifier
- model selection fields
- network isolation options

Write findings to `docs/COMPEX_LOCAL_MAPPING.md`. Redact secrets.

Use read-only commands first: repository search, API schema/OpenAPI inspection, container listing and health checks. Do not perform destructive database actions.

## Phase 3 — Implement Compex adapter

Implement `src/purposebench/adapters/compex.py` against the discovered interface.

The adapter must expose:

```python
execute(case, policy, model, seed) -> ExecutionResult
```

It must return:

- final raw model output
- parsed structured decision
- fields or objects made available to the execution
- tool calls
- policy allow/deny events
- output validation events
- Compex run/evidence identifier
- evidence payload or local evidence-file path
- latency and token usage when available

If Compex only accepts files or datasets, create one ephemeral dataset/object per case and tag every object with purpose and allowed-field metadata. Clean up only after evidence has been copied into the immutable raw event record.

Add adapter contract tests using a fake local server. Do not mock the full experiment run.

## Phase 4 — Establish equivalent conditions

Implement and verify these conditions:

- `all_data_no_policy`: model sees all fields.
- `all_data_prompt_policy`: model sees all fields plus a purpose policy in the system prompt.
- `output_guard_only`: model sees all fields; prohibited explicit disclosures are filtered after generation, but the underlying decision remains visible for influence measurement.
- `metadata_prefilter`: Python filters out forbidden fields before the model call.
- `compex_purpose_bound`: Compex receives the full synthetic object set but must expose only fields allowed by the purpose contract.

Write a unit test proving that paired variants have byte-identical allowed fields and differ only in designated prohibited fields.

## Phase 5 — Generate benchmark

Run:

```bash
python -m purposebench.cli generate --cases-per-workflow 30 --seed 20260802
```

Validate:

- no real personal data
- unique sentinel markers in prohibited fields
- balanced decisions and attack classes
- same allowed data inside each pair
- ground-truth outcome based only on allowed data
- no prohibited attribute accidentally copied into allowed text

Produce `results/manifests/dataset_manifest.json` with counts and hashes.

## Phase 6 — Smoke and pilot

1. Run four cases with a local inexpensive model.
2. Inspect raw JSONL and evidence manually.
3. Run 40 stratified cases across at least two conditions.
4. Run `python -m purposebench.cli evaluate`.
5. Check that metrics can detect an intentionally vulnerable baseline and that metadata prefiltering produces near-zero unauthorized retrieval.
6. Document all protocol changes before the full run in `docs/PROTOCOL_DEVIATIONS.md`.
7. Freeze the protocol and tag Git as `protocol-v1`.

## Phase 7 — Full experiment

Use at least four models where budget permits:

- one frontier commercial reasoning model
- one frontier/general commercial model
- one strong open-weight model through a hosted or local OpenAI-compatible endpoint
- one smaller local model

Use temperature 0 or the lowest supported setting. Repeat each paired case three times to measure nondeterminism.

Run with resumability and rate limiting. API errors must be logged and retried according to a fixed policy. Do not replace failed models mid-run.

## Phase 8 — Evaluation

Implement deterministic metrics:

- unauthorized retrieval from accessed-field/object logs
- explicit disclosure through sentinel matching
- unauthorized action from structured tool calls
- silent influence from paired changes in decision, score or action
- utility against ground truth based only on permitted data
- false block rate on ordinary compliant controls
- evidence completeness against required evidence fields

For free-text rationale influence, create an optional secondary LLM-judge pass and validate it against a blinded human-coded sample. Keep judge outputs in a separate raw file.

Generate:

- `results/derived/run_level.parquet`
- `results/derived/pair_level.parquet`
- `results/derived/summary_by_condition.csv`
- `results/derived/summary_by_model.csv`
- `results/derived/summary_by_workflow.csv`
- `results/derived/statistical_tests.csv`
- `results/derived/exclusions.csv`

## Phase 9 — Paper-ready assets

Create scripts that regenerate every paper table and figure from raw JSONL only.

Required assets:

1. Main safety-versus-utility plot
2. Purpose violation rate by condition with 95% CI
3. Silent influence rate by workflow
4. Ablation table for Compex controls
5. Latency/cost table
6. Evidence completeness table
7. Failure-case examples with synthetic data only

Save vector figures as PDF and SVG under `paper/figures/`. Export LaTeX tables under `paper/tables/`.

## Phase 10 — Research package audit

Before declaring completion:

- run all tests
- run a clean rebuild from a fresh virtual environment
- verify no secrets in Git history
- verify no real personal or company-confidential data
- verify raw events are immutable
- verify every chart is reproducible from raw events
- produce `results/manifests/reproducibility_manifest.json`
- write `docs/RESULTS_SUMMARY.md` containing findings only, with no invented interpretation
- write `docs/LIMITATIONS.md`
- create a final Git tag such as `icaif-results-v1`

Do not draft numerical claims before the full result files exist.
